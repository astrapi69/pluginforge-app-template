# Configuration

MyApp uses a four-layer config chain so secrets stay out of the
project tree and the Settings UI never owns sensitive values.

```
┌──────────────────────────────────────────────────────────┐
│ env-vars (CI/Docker, highest priority)                   │
│ MYAPP_SECRET_KEY, MYAPP_ANTHROPIC_API_KEY,               │
│ MYAPP_OPENAI_API_KEY, MYAPP_GEMINI_API_KEY,              │
│ MYAPP_AI_API_KEY (legacy single-provider slot)           │
└──────────────────────────────────────────────────────────┘
                  ↑ overrides
┌──────────────────────────────────────────────────────────┐
│ user secrets file (auto-created, gitignored, chmod 0600) │
│ ~/.config/myapp/secrets.yaml                             │
└──────────────────────────────────────────────────────────┘
                  ↑ overrides
┌──────────────────────────────────────────────────────────┐
│ user-overlay app.yaml (Settings UI writes here)          │
│ <data_dir>/config/app.yaml                               │
└──────────────────────────────────────────────────────────┘
                  ↑ overrides
┌──────────────────────────────────────────────────────────┐
│ project app.yaml (committed defaults)                    │
│ backend/config/app.yaml                                  │
└──────────────────────────────────────────────────────────┘
```

Override-wins semantics: a value in a higher layer replaces the
same key in any lower layer. Lists are **replaced**, not merged.

---

## Where to put what

| Layer | Examples | Lives in |
|---|---|---|
| Project `app.yaml` | non-secret defaults: `app.name`, `editor.autosave_debounce_ms`, `plugins.enabled` | committed to git |
| User-overlay `app.yaml` | per-user UI/editor preferences, written by the Settings tab | `<data_dir>/config/app.yaml` (resolves via `MYAPP_DATA_DIR` / platformdirs) |
| User secrets | API keys, signing secret: `ai.anthropic.api_key`, `secret_key`, etc. | `~/.config/myapp/secrets.yaml` (Linux/macOS), `%APPDATA%/myapp/secrets.yaml` (Windows) |
| Env-var | CI/Docker secrets injected by the orchestrator | environment |

**Rule of thumb:** anything sensitive belongs in the secrets file
or env-var. Nothing sensitive belongs in `app.yaml`.

## Per-provider AI keys

The Settings UI now resolves a separate slot for each AI provider
plus a legacy slot:

| Path | Env-var | Notes |
|---|---|---|
| `secret_key` | `MYAPP_SECRET_KEY` | top-level slot for the app secret (auto-generated by `start.sh` when unset) |
| `ai.api_key` | `MYAPP_AI_API_KEY` | legacy single-provider slot; still read by current AI consumers |
| `ai.anthropic.api_key` | `MYAPP_ANTHROPIC_API_KEY` | Anthropic / Claude |
| `ai.openai.api_key` | `MYAPP_OPENAI_API_KEY` | OpenAI / GPT |
| `ai.gemini.api_key` | `MYAPP_GEMINI_API_KEY` | Google Gemini |

The legacy `ai.api_key` slot is kept because two backend consumers
([`app/main.py`](../backend/app/main.py) and
[`app/ai/routes.py`](../backend/app/ai/routes.py)) still read it.
A separate follow-up migrates those consumers to read from the
per-provider paths.

## Path resolution per OS

Resolved via `app.paths.get_config_dir()` (which uses
[platformdirs](https://pypi.org/project/platformdirs/)).

| Platform | Default |
|---|---|
| Linux | `~/.config/myapp/secrets.yaml` (honors `XDG_CONFIG_HOME`) |
| macOS | `~/.config/myapp/secrets.yaml` (platformdirs uses XDG semantics for `user_config_dir`) |
| Windows | `%APPDATA%/myapp/secrets.yaml` |

Override with `MYAPP_CONFIG_DIR=/srv/configs` to relocate without
touching `XDG_CONFIG_HOME`. The test conftest uses this hook to
point at a tmp dir.

## Auto-generated template

On first start, the backend auto-creates `~/.config/myapp/` and
writes a commented-out `secrets.yaml` template at
`<config_dir>/secrets.yaml` with chmod `0600`. The template is
inert until the user uncomments and fills in values:

```yaml
# MyApp - API Keys
# Uncomment and fill in your keys below.
# These take precedence over keys configured in the Settings UI.
# Environment variables override this file.

# secret_key: "generate-with-python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'"

# ai:
#   anthropic:
#     api_key: "sk-ant-..."
#   openai:
#     api_key: "sk-..."
#   gemini:
#     api_key: "AIza..."
```

Two startup log lines surface the location:

```
INFO  app.main: Config directory: /home/<user>/.config/myapp
INFO  app.main: Secrets template created at /home/<user>/.config/myapp/secrets.yaml
```

Auto-creation is skipped under `MYAPP_TEST=1` so the test suite
never touches the user's real config dir.

## Permission warning

When the secrets file is group- or world-readable (mode bits other
than the owner's), the loader emits a single WARNING per path per
process:

```
WARNING: Secrets file /home/.../.config/myapp/secrets.yaml has
permissive mode 644; recommend chmod 600.
```

The dedup keeps the warning from spamming the log (the override
file is read per-request). On Windows the check is a no-op
because the ACL model is different.

## Detecting which layer wins (`_secret_sources`)

`GET /api/settings/app` returns two meta-fields the frontend uses
to gate inputs:

```jsonc
{
  // ... app / author / plugins / ai / ui / editor sections ...

  "_secret_sources": {
    "secret_key":            "settings",
    "ai.api_key":            "settings",
    "ai.anthropic.api_key":  "env",
    "ai.openai.api_key":     "file",
    "ai.gemini.api_key":     "settings"
  },
  "_secrets_file_path": "/home/<user>/.config/myapp/secrets.yaml"
}
```

Per-key source values:

- `"env"` - a matching `MYAPP_*` env-var is set (highest precedence).
- `"file"` - `secrets.yaml` has a non-empty value at that path.
- `"settings"` - neither, so the Settings UI is the source of truth.

The frontend renders a source label per provider in the Settings
tab and the first-run wizard. When the active provider's key
source is `file` or `env`, the input field is replaced by an
info-note showing the source label + (for file sources) the
resolved path. The save button stays enabled so the user can
still change sibling AI fields (model, temperature, etc.); only
the externally-managed key is dropped from PATCH bodies (server-
side strip, defense-in-depth).

Quick probe:

```bash
curl http://localhost:8000/api/settings/app | jq '._secret_sources, ._secrets_file_path'
```

## Migration: move legacy `ai.api_key` out of `app.yaml`

If `backend/config/app.yaml` still carries `ai.api_key` inline,
migrate to the secrets file:

```bash
# 1. Template is already auto-created on first start; if not, run
#    the backend once to create the parent dir.
ls ~/.config/myapp/

# 2. Edit the template:
$EDITOR ~/.config/myapp/secrets.yaml

# 3. Uncomment the per-provider block(s) and paste your real key:
#    ai:
#      anthropic:
#        api_key: sk-ant-api03-your-real-key-here

# 4. Empty the api_key in backend/config/app.yaml.
#    The backend logs a deprecation warning while a non-empty key
#    sits there alongside no override; emptying silences it.

# 5. Restart the backend.
make dev-down && make dev
```

Result: the Settings tab and AiSetupWizard hide the API-key input
automatically (via the `_secret_sources` meta-field) and show an
info-note with the file path so the user knows where the key
lives.

## Docker / CI usage

```yaml
# docker-compose.prod.yml (example excerpt)
services:
  backend:
    image: myapp:0.33.0
    environment:
      MYAPP_ANTHROPIC_API_KEY: ${MYAPP_ANTHROPIC_API_KEY}
      MYAPP_OPENAI_API_KEY:    ${MYAPP_OPENAI_API_KEY}
      MYAPP_SECRET_KEY:        ${MYAPP_SECRET_KEY}
      MYAPP_DEBUG: "false"
    volumes:
      - ./config:/app/backend/config
```

Inject env-vars from CI secrets (GitHub Actions secrets, GitLab
CI variables, Vault, etc.). The project `app.yaml` keeps the
provider key fields empty so env-vars win on merge.

## Plugin-yaml secrets (deferred)

Plugin-yaml secrets (audiobook, grammar, translation) are NOT yet
covered by this mechanism - they load via PluginManager and need
a parallel refactor (T-XX Plugin-Config Secrets Layering,
deferred). For now, those keys live in their respective
`backend/config/plugins/*.yaml` files; the Settings UI for each
plugin still writes back there.

## Deprecation warning

When `app.yaml` carries a non-empty `ai.api_key` AND no override
file value AND `MYAPP_AI_API_KEY` is unset, the backend logs a
one-shot WARNING at startup:

```
WARNING: Secrets found in /path/to/backend/config/app.yaml
(ai.api_key). This file is gitignored but may be committed
accidentally, end up in backups, or appear in screen-shares. Move
secrets to /home/.../.config/myapp/secrets.yaml or set
MYAPP_AI_API_KEY. See docs/configuration.md for details.
```

The warning is informational. Existing installations with a
hardcoded key keep working unchanged; this is a migration nudge,
not a breaking change. The check only fires for the legacy
`ai.api_key` slot; the per-provider paths are new and have no
legacy-in-project-yaml shape to detect.
